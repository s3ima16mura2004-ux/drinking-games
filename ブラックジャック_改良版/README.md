# 宴会ブラックジャック(リアルタイム複数端末版)セットアップ手順

## ファイル構成
```
(リポジトリのルート)
├── index.html            ← 3つのページへのリンクをまとめた入口ページ
├── html/
│   ├── index.html        ← 1台で遊ぶ版(前バージョン)
│   ├── host.html          ← 共有画面(みんなが見るテレビ・PC用)
│   └── player.html        ← 各プレイヤーが自分のスマホで開くページ
├── css/
│   ├── style.css          ← 1台で遊ぶ版のスタイル
│   └── common.css         ← リアルタイム版(host/player)共通スタイル
├── js/
│   ├── script.js          ← 1台で遊ぶ版のロジック
│   ├── firebase-config.js ← ここに自分のFirebase設定を書く
│   ├── host.js
│   └── player.js
└── images/
    └── 01.png 〜 52.png, red.png, blue.png, board.png
```

画像はすべて `images/` フォルダの中に置いてください。コード側は `images/01.png` のような形で参照するように直してあります。

## 1. Firebaseプロジェクトを作る

1. https://console.firebase.google.com/ を開き、Googleアカウントでログイン
2. 「プロジェクトを追加」→ 好きな名前(例: `enkai-blackjack`)を入力して作成
3. 作成したプロジェクトの画面で、左メニューの「構築」→「Firestore Database」を開き、「データベースの作成」
   - ロケーションは `asia-northeast1(東京)` などお好みで
   - セキュリティルールは、まず「テストモード」で開始してOK(後述のルールに書き換えます)
4. 左メニューの「プロジェクトの概要」の歯車アイコン→「プロジェクトの設定」→ 下の方の「マイアプリ」で「ウェブアプリを追加」(`</>`アイコン)
   - アプリのニックネームは何でもOK(Firebase Hostingは使わないので、そのままの手順で進めてください)
5. 表示された `firebaseConfig = { apiKey: ..., authDomain: ..., ... }` の中身をコピーして、
   このフォルダの `firebase-config.js` の `firebaseConfig` オブジェクトに貼り付けて置き換えてください。

## 2. Firestoreのセキュリティルールを設定する

「Firestore Database」→「ルール」タブで、以下のように書き換えて公開してください。
このゲームはログイン機能を作っていないので、ルームコードを知っている人だけが
読み書きできる、という緩めのルールにしてあります(合コンや飲み会の身内利用が前提です)。

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /rooms/{roomCode} {
      allow read, write: if true;

      match /players/{playerId} {
        allow read, write: if true;
      }
      match /actions/{actionId} {
        allow read, write: if true;
      }
    }
  }
}
```

> ⚠️ 誰でも読み書きできるルールなので、大事なデータを置くプロジェクトとは
> 必ず別のプロジェクトにしてください(今回「新しいプロジェクトを作る」を選んだ理由もそこにあります)。

## 3. 公開する(GitHub Pages でOK)

`realtime_bj` フォルダを、いつも使っているリポジトリにアップロードして
GitHub Pages で公開すれば、そのままスマホからアクセスできます。

- 入口ページ: `.../(リポジトリ名)/`(3つのページへのリンク一覧)
- ホスト用URL: `.../(リポジトリ名)/html/host.html`(お店のテレビやノートPCで開く)
- プレイヤー用URL: `.../(リポジトリ名)/html/player.html`(各自のスマホで開く)

Firebase の JS SDK を `https://www.gstatic.com/...` からモジュールとして読み込むため、
`https://` で配信されている必要があります(GitHub Pagesは標準でhttps対応なのでそのままでOKです)。
`file://` で直接ダブルクリックして開くと、ブラウザの制限でモジュール読み込みが失敗するので注意してください。

## 4. 遊び方

1. お店/共有の画面で `host.html` を開き、「ルームを作成」→ 4桁のコードが表示される
2. 各自のスマホで `player.html` を開き、コードと名前を入れて「参加する」
3. 2人以上参加したらホスト側で「ゲーム開始」
4. 各自のスマホで「引く」「勝負する」を操作(自分の番が来ると通知されます)
5. 全員終わるとディーラーが自動で引き、結果発表。負けた人は自分のスマホで罰ゲームみくじをタップ
6. ホスト側の「次のラウンドへ」で連戦できます

## 既知の制限(今回のスコープ外)

- ホスト画面をリロードするとその場のゲーム進行状況(手札・山札)は失われます(ロビー作成からやり直しが必要)。長時間の安定運用が必要なら、ホスト側の状態もFirestoreから復元する仕組みを追加できます。
- 通信が不安定な環境では、操作の反映に数秒のラグが出ることがあります。
- 同時に大量の部屋を捌く用途は想定していません(あくまで身内の飲み会向けです)。
